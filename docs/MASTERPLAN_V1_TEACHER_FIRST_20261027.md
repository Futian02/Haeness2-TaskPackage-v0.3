## 1. 项目定位：赢在哪里
真实工程师处理常减压装置设备异常时，需要识别可能损伤机理、检验依据、进行严肃的 RBI 风险研判、指出下一步现场证据。不允许凭模型记忆杜撰标准或设备风险等级。
项目不是普通问答机器人，而是 **Standards-grounded Evidence-constrained Decision Agent**。
系统要达到：
- **合规**：老师的三工具、八段式、字段、枚举、转换和JSONL全兼容，所有终验过关；
- **可信**：每一条断言对应真实 clause_id、适用范围、证据强度；低证据时明确“不足以定级”；
- **高效**：关键词/索引检索在毫秒量级基础上，对模型轮次、上下文长度和额外审核次数做优化；
- **可解释**：公开决策依据、工具名/参数/返回/观察、候选排除过程；不曝光模型私有内在推理；
- **可展示**：ModelScope公开网页，可切换规则与模型、显示相同问题的过程和引用详情、4类情景截图；
- **有科学比较**：LLM vs rule，官方词法 vs FTS5 vs hybrid，单agent vs reviewer，报告准确率、成本和P50/P95，保留失败样本。

## 4. 顺序 Gate（每过一关才能合格宣称）
### G0 完整材料（立即）
执行 `git -C upstream sparse-checkout disable` 使**整个Git版本中所有文件**进入工作树，包括标准PDF、XLSX、samples、第三方 reference_code 和现存渲染缓存。上游是独立仓库，保持HEAD、禁止清理/提交到父仓库；先审计磁盘空间、总文件数/目录大小、下载完成率、损坏对象、git status。
自动脚本 `scripts/check_sources.py` 从当前9/19进阶到19/19，额外出全仓MANIFEST(path,size,sha256,role,origin,editable)；清单本地存 `docs/audits/`。
无需把上游所有文件复制到外层；**单独的upstream/即为完整同步**。
### G1 证据链（数据优先）
选随机50条（记录seed）逐条对标准PDF页码、原文≤300字、适用材料/介质/温压验证；检查Excel源表header（RBI23列、DM25列）、clause_no文本（5.10不是5.1）、运行convert dry-run比较，不直接覆盖官方JSONL；研究回溯E0/E1/E2/E3。
带数据质量报告的精确定义：source clause_id真实、content_raw真实、条件未外推、quote支持最终断言，四层不能简化为“有引用就是对”。
### G2 可运行LLM/Harness
官方 RulePlanner 保留回归基线；实现LLM adapter的原生结构化工具调用，将 `parsed_ok,parsed_fail,fallback,invalid_args,error` 分拆；校正路径相关`_df_rules`等异常隐患。真实API先10例，再100例BFCL AST，报告 95/100 门槛；构造≥5连续调用用例和100日志完整性用例。上游涉及修改在独立分支，先红后绿、两份Harness保持镜像一致。
### G3 工程语义与检索
冻结50~100题（术语/模糊现场描述/混淆/反证/OOD/RBI同名矩阵），建人工ground truth的clause_id集合和适用条件；先用当前 `standard_clause_search` + SQLite FTS5；若语义描述失效，再引embedding + RRF + rerank **旁路A/B**。保留 clause_id、standard_code、clause_no、page，不让向量绕过材料介质温度过滤；缺现场因素只返回下一步证据，不幻觉生成L1~L4。
### G4 本地产品与公网部署
先本地Gradio完整真实流输入/步骤/引用，证据和日志可折叠、单步与多步回放、术语tips、多种异常信息。用户可复制/下载结构化审计摘要（不暴露企业/私密信息）。敏感 key仅环境变量，公众请求限速、超时、并发限制；在ModelScope Space部署，人工现场输入+四类截图；保存commit/hash/模型版本/成本。
### G5 20%加分中的高性价比
优先A **轨迹审查与自动质量评分器**（教师明确推荐），B **排除式机理研判+主动补证据**（教师第二推荐）；C 标准条款冲突检测可做高质量小demo，D 对抗护栏测试生成可选。
可加分的核心是**有证据的机制与对照**，不是堆3个大模型。审查体必须实测降低错误引用/误定级而非仅消耗token；不改官方3工具的对外协议。

## 5. 高分展示的故事线（严格来源约束）
故事：凌晨塔顶铁离子异常→工程师给出材质/介质与现场现象→候选3机理→证据区分/排除→缺少H2S浓度、注水点与检验历史→不妄定级→提供标准具体页码与下一步测量/检验建议。再演示：改一个真实观测（例如检测未发现减薄），候选为什么变化？以及“故意输错工具参数”为何被拒绝。
让评审看到**思路如何随证据而更新**。UI应显示外显决策摘要/工具过程，不强求显示模型内部私有chain-of-thought。

## 6. 六项指标与决策门槛（建议，不冒充老师要求）
- ParseSuccess (无fallback)：≥95%（官方100例）。
- EvidenceTruth/E3准确率：越高越好，须人工金标；官方随机50条≥95%。
- AbstentionCorrectness：正确缺信息拒判、错误硬答率；重点优先降低误硬答。
- MultiStepValidity：≥5轮不作弊；100%可重放轨迹和操作统计。
- EndToEnd P50/P95：按规则/单LLM/审查两LLM分别统计，采集网络与token；目标候选复杂问题P95<20s仅为建议，非既成。
- Latency分解：query parse、lexical/dense/rerank、每个LLM call、工具、reviewer、UI串流；避免把毫秒级检索优化当主胜负手。

## 7. 具体每轮节奏（不做后台承诺）
- 每轮由 ChatGPT给一个冻结的阶段目标与验收表，Codex在本地一次只接一个原生线程任务，取回结果后ChatGPT独立验收并记录。
