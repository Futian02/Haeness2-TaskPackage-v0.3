# 第1课：Agent 到底与普通程序差在哪里？

学习目标：结合已经存在的 `upstream/05_提交区/harness.py`，理解 Agent 不是“多个模型聊天”，而是一个**带状态、能选动作、能接收环境反馈、受护栏约束的控制循环**。

## 1. 前世今生（极简梳理）
- 经典规则系统：`if 条件 -> then 结论`；可预测，但只能覆盖已写好的情况。
- 搜索和规划：把问题表达为状态、动作、代价、目标，然后规划动作序列（如 A*、STRIPS）。
- ReAct：把行动与外部观察串起来，让语言模型能够根据工具返回改变下一步，而不只是一次性生成答案。
- 现代 Harness：模型/规则决策器只是其中一个组件，外面还有工具注册、参数校验、执行循环、异常、审计和轨迹导出。**可靠性是整个执行系统的属性**。

## 2. 用数学语言描述运行
把第 t 轮的可见状态记为 `s_t`，由规划器 `π` 选择动作 `a_t = π(s_t)`；调用工具后得到观察 `o_t = Tool(a_t)`，由运行时更新状态 `s_{t+1} = T(s_t, a_t, o_t)`。当判定足够或达到最大轮次时停止。

这里：
- `π` 对应 `RulePlanner` 或 `LLMPlanner`；
- `a_t` 对应 `{"tool": ..., "args": ...}`；
- `Tool` 对应三种老师冻结的查询工具；
- `T` 对应 `Harness.run` 把 Step 追加到 history；
- 安全约束对应 `Guardrail`，并不由模型自己决定。

如果用状态机画：输入 -> 规划器 -> 参数检查 -> 工具执行 -> 观察 -> 更新history -> 下一轮规划；出口包括正常final、达到轮次上限、护栏阻断与工具异常。

## 3. 用真实仓库代码对应一次交互
问题：“碳钢换热器、湿硫化氢、110℃、pH=5.8，可能是什么机理？”
1. `RulePlanner` 选择 `damage_mechanism_query`；
2. `Guardrail.check_tool_exists/check_params` 拒绝未知工具、介质字符串、未知参数；
3. `tools.damage_mechanism_query` 查 `clauses.jsonl`，返回 `source`；
4. `Harness._summarize` 为下一轮提供工具观察；
5. 有多个候选可触发 `standard_clause_search`，查辨别依据；
6. `rbi_lookup` 尝试严肃风险级别判定；因现场因子不全，返回判定路径并保留 `null`；
7. `final_answer.basis` 列出实际查询中的证据。**模型不应仅因术语“高风险”就臆造等级**。

## 4. 最值得做的四个对照实验
A. 只用固定规则：能回答哪些场景？在哪些工况上没有弹性？
B. LLMPlanner：把相同输入交给模型，记录合法工具调用、完成率、Token、P95延迟；
C. LLMPlanner 带规则回退：成功率如何变化？注意单独统计“LLM原生成成功率”；
D. 再加审查体：证据无依据断言率是否明显下降？是否值得额外延迟？

如果 D 的表现不如 C，就不需要为了“多智能体”的名头保留审查体。

## 5. 关键区分：引用存在 vs 引用成立
`basis` 里的条款 ID 在库中存在，并且本轮工具返回过它，只能说明**出处存在**；不能说明“条款真的支持当前这个设备工况和结论”。第二层还需人工核原文适用材料、介质、温度以及逻辑蕴含关系。整个安全性依赖这个差异。

## 6. 第一次讨论题
当大模型在第2步没有查到足够证据时，我们希望它选择什么？
(1) 改用不同查询词再次检索；
(2) 请求补充现场证据；
(3) 直接给最可能机理但标明低置信度；
(4) 拒绝定级但继续给出下一步可执行的检查清单。

直觉可能偏向 (1)+(2)+(4)，但何时停下、如何界定“足够证据”是我们之后要共同设计的核心，也是最值得写成论文或答辩亮点的研究问题。

## 7. 延伸阅读
- ReAct (Yao et al., 2022/2023) — 将推理与行动交织；学习时重点看 tool observation 如何影响下一轮 action。
- LangGraph (langchain-ai/langgraph) — 了解状态图、checkpoint、人工审查，但不必立刻迁移现有 Harness。
- BFCL (ShishirPatil/gorilla) — 区分语法解析、工具选择、参数正确、跨轮规划等不同指标。
- Ragas (vibrantlabsai/ragas) — 学习事实支持率如何与召回率区分。
