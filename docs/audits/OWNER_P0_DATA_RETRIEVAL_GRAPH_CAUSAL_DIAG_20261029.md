# Owner补充诊断｜Aetheris专业问题反复拒答的“数据—检索—Graph”根因（2026-10-29）

**状态：ROOT_CAUSE_SPLIT_EVIDENCED / READ_ONLY_DIAGNOSTIC / NO_PRODUCTION_MUTATION。**
本轮只读官方`upstream/05_提交区/clauses.jsonl`及冻结`standard_clause_search`工具，未修改老师源、索引、业务DB、运行中的服务。Codex当前P0专业回答修复请将本报告作为补充负例与验收输入，但不要改写P0工作区对他人的未提交文件。

## 一、故障不是一个原因
- **A：网页里给300系列不锈钢、碱式酸性水、60℃仍被索要材料/介质。** 最新磁盘`extract_explicit_context`能识别5字段，R9本地2次工具/6来源/1候选；而运行中8000旧Python API未包含新版本模型接口。这一题优先核对真实run input snapshot与PID加载版本，不应指责最新source缺A的知识。
- **B：问“设备发生壳体磕碰损伤，什么情况需要停机维修？验收判定标准是什么？”直接unresolved。** 最新R9本地2工具0来源，说明即使更新后端仍会失败。它是**任务/检索策略/知识范围/回答政策**叠加。

## 二、正式知识覆盖：54x中554条实际分布
- 正式`clauses.jsonl`读到554条，其中rbi=472、damage_mechanism=82。数据结构校验554/554、200轨迹是**机器合同一致性**，不能当通用机械工程问答覆盖率或标准专业准确率。
- 以JSONL字段值全文字符串匹配观察B词汇：磕碰0、验收0、碰撞1、撞击2、凹陷1、机械损伤6、修理1、维修2、壳体9、检验473、裂纹86、减薄56。**这只是词面覆盖，不能证明某条标准法定支持/不支持具体维修要求。** 教师允许的数据集天然偏RBI和损伤机理，不是全面的承压壳体损伤验收和停复机法规知识库。
- DM82结构化medium26/82、temperature界23/82、pressure界0/82、verified_by0/82。S3-A候选134谓词/15机理/0人工approved，S3-B三值引擎有效但目前不允许利用未经复核条件做硬排除。因而不仅召回，**设备条件适用性也不完整**。

## 四、Graph和模型同时限制了答复
- R9`route_task/evidence_gate/_report`有material/medium缺→ask_user、无citation→unresolved硬返回；“不满足设备级确诊”被误扩张成“不允许解释一般工程知识”。
- `backend/deepseek.generate_report`系统提示要求只改写deterministic_result，不负责检索/诊断/复核；API用户主答仍以R9结论为主，模型产生的文本只出现在折叠的过程事件中。**模型不能改变检索策略、不能自动补救ZERO_SOURCE，也不能输出有用的公开初步分析**。
- A缺字段还叠加旧8000运行版本；这不是提高RAG数据量即可解决的。

## 五、Codex P0工作合同建议加固
1. **检索前**：从`壳体磕碰/维修/验收`识别`mechanical_damage`+`pressure_boundary_integrity`+`repair_acceptance`三个子目标，生成3–5个有界关键词。记录原始query、改写query、每次source数量/ID；失败不得无限重试同义词。
2. **检索后**：基于设备对象、损伤机理、法规类型、原始短摘录语义和条款适用范围重排；以上“碰撞 凹陷→辐照脆化”必须拒为不相关，勿将模型相关性自评冒充人审。
3. **知识覆盖边界**：官方三工具和554条源冻结。若老师合同未覆盖“停机与维修验收”的完整强制依据，明确标`STANDARD_NOT_VERIFIED`，仍可提供不伪装成法规的事故初步风险识别与检查建议；不能编造统一法定凹陷阈值、复机许可或正式风险等级。
4. **F1回答独立于F2来源**：用户能得到一般工程条件分析、区分因素、危险信号、现场核查清单、需补资料的精确理由；F2仅展示确实核过的条款，F4确诊/强制数值仍严格限制。
5. **发展数据源**：先建立*知识需求覆盖矩阵*（工况类型×用户问题类型×支持来源×许可等级×缺口），再按合法授权分批引入修理/验收/检验/通用机械损伤知识，而不是把82条机理扩写当成完整行业知识。将知识层拆为：教师冻结标准、派生结构化适用性候选、通用工程知识（来源许可明确）、按设备法规独立验证层。不要将生成文本直接加入标准库。
6. **自动验收分母**：对至少50条含原问/改写/困难负例查询比较Old vs New，在**同一冻结官方语料**上分开报告查询覆盖、Recall@5/Precision@5(仅人工审标则作gold)、False Citation、Unsupported Standard Claim、Answer Usefulness(人工标准评分)、缺工况的合理调查率、延迟/成本。应包含用户两个真实截图原问，与“无同主题标准来源”的真知识缺口案例。不能单用返回结果数量和新测试100%说明改善。
7. **运行版本**：API contract_version、8000 PID源码版本、输入事件及run快照、前端主回答对齐，否则用户看到的仍是旧版本响应。

目标不是“编一些看似专业的结论”，而是把有据检索与广义专业假设隔离，使**问题有增量调查和有行动价值回答**。本报告不代替人工标准适用性复核或真实网站端到端验收。
