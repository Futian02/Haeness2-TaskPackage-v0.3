# 本地优先的机械智能体网站产品规格 V1

## 前端目标
参照现代对话产品的用户体验：不是复制某家产品源码或商标，而是清晰流畅的**聊天 + Agent进度 + 审计详情**。
核心页面三栏响应式：左导航历史会话/新建/搜索；中部消息流、工况表单、流式回复与场景快捷样例；右侧Agent执行时间线、证据卡、候选机理差异、审查报告。移动端右栏折叠为抽屉。
主题建议工业科技的深灰/青蓝浅色双主题、交互态显著、状态标签简洁；不以视觉特效取代真实数据。

## 交互信息架构
- 消息输入可使用自然语言，并可展开填写结构化设备/材质/介质/温度/压力/现象（正式工具参数仍是老师规范）。
- 工况校对页面展示解析结果：unknown/未测量，不自动变false。
- Agent运行时按SSE事件更新：已接收→工况抽取→标准检索→机理鉴别→RBI评价→证据审查→结果生成；节点并行、跳过、失败/退回有清晰原因。
- 用户可点击打开每轮tool名称、参数、简要结果、耗时和引用条款，提供标准页码和小段原文摘录（注意版权与来源许可）。
- 最终结果：候选机理按支持/反证/缺证据对比，真实风险等级为null时显示“尚无法定级”，列出下一步现场检查条件。
- 记忆：SQLite记录session/messages/runs/events/evidence refs，使用唯一session ID；多用户隔离，默认本机单用户模式。Mysql optional：只有产生真正多用户部署需求时才切换。
- 流式接口应该能断线续读event cursor，而不是靠前端刷请求重跑LLM造成额外收费；输出可复制的审核摘要。不要公开隐藏思维链，只展示能解释给用户的行动依据。

## 前后端候选
FastAPI + Pydantic + SQLAlchemy SQLite（本地），LangGraph StateGraph SQLite checkpoint；React/Vite + Tailwind + shadcn/ui + 轻量SSE/AG-UI；若采用CopilotKit，其license和当前适配版本必须事先核实。保留现有Gradio `app/web.py` 老师ModelScope演示路径。
不要直接copy OpenWebUI整站改品牌；它近期有品牌保留条件和较重依赖。

## 部署路线
0本机：FastAPI和React本地，SQLite持久与LLM key本机环境变量。
1评审：Gradio+ModelScope公共URL满足老师技术指标，脱敏样例/限流。
2域名：仅用户明确授权且提供可用服务器与DNS权限后部署（建议容器/反向代理、HTTPS、简单鉴权、请求速率限制、数据库备份）；免费额度与持久磁盘是否支持，需按当时平台真实政策查，不能保证永久免费。
3运营：监测使用量、响应P95、错误率、费用、速率限制，避免外部攻击耗光模型额度。

## 验收任务
真实输入产生一条带run_id的完整过程；刷新/重开可恢复本地历史，别的会话不能串；切换无API模式明确提示；页面响应/超时/异常可见；官方4种截图至少single/multi/guardrail/OOD；不得声称模型内部未公开思维链可见。
