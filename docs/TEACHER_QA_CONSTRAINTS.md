# 教师《任务包问题答复.docx》核对笔记
来源：`upstream/任务包问题答复.docx`，本轮直接使用 python-docx 读取 121 段、2 张表（2026-10-27）。
这是用户端团队在2026年9月24日提出问题后，教师于9月25日给出的v0.3答复，属于老师合同的权威补充。
**下列摘要用于工程实现，遇歧义仍查原docx与接口规范。**

## 1. 不可改变的结构
- 损伤机理摘录表 25 列、RBI 摘录表 23 列，表头和列顺序不许改；损伤机理固定八段式，GB/T 30579-2022 第4.4条。
- `risk_level_mapping.xlsx` 不许修改；风险矩阵低/中/中高/高对应 L1–L4，老师任务包不会给L5。
- `clause_no` 一定用Excel**文本**，不能用数字；标准中5.1与5.10含义截然不同，数字化会污染ID与引用。
- 两类原始 `xlsx` 是转换的唯一上游，`convert.py` 才能生成 `clauses.jsonl`；原文摘录不可改写、长度≤300字，OCR输出必须逐字对PDF检查。
- 工具接口以 `04_接口文档/工具接口规范.md` 定稿；只允许三个既定工具；成功来源不能为空。
- `applicable_conditions.material` 只用规范枚举，而 `mechanism_detail.affected_materials` 保留原文材质，包括枚举外材料。材料族只能由牌号向上展开，不能类别向下推断。

## 2. 数据与版权边界
- 只用任务包中GB/T和TSG21相关标准。API 510/570/571/580/581及NACE/AMPP为收费版权资料，不纳入 `clauses.jsonl`；不得公开传播盗版资料。
- 企业设备台账和内部工艺手册不在本课题范围，不能为方便“知识增强”随意加入公网检索库。
- TSG21-2016 的第1号修改单需核对受影响条款，不能只看旧PDF。
- GB/T 26610.3-2014属于定性风险方法，等级由6个可能性因子加权/累加后再按矩阵与后果等级确定；缺装置级数据不能仅按损伤机理定级。

## 3. 轨迹/护栏约束
- 多步 `multi_step` 以**≥3次工具调用**计；不要求三种不同工具，但重复一个工具只换参数凑步数是无效记录。
- `special_type` 与调用次数独立；`exclusion`、`insufficient_info` 可仍为 `single_step`。
- 被护栏拦截的步骤只能写运行日志 `to_dict()`，不能进入训练数据集 `to_record()`。
- `validate.py --final` 同时检测 Schema、数据配额、ID引用和task_type，*不证明*模型独立规划。
- Windows 下用官方 `save_jsonl()` UTF-8写文件；不要通过 CMD/PowerShell 5.1 `>` 重定向写训练数据，编码会错。

## 4. 交付与学习上的推论
- 工具由老师限定，是**我们应该深入学的最小接口约束**，无需重新实现 LangChain Tool层来满足验收。
- 教师指定参考代码/框架可作为知识来源，**不需要把别人完整代码复制进最终仓库**；本次约束更强调可运行、可追溯、能解释每次动作。
- 前端展示用户可核的行动摘要，而非模型隐藏思维；数据闭环中断时要记录原因。
- 复核签字须真实，绝不自动填假 `verified_by` 或将未复核数据标 `checked=true`。
