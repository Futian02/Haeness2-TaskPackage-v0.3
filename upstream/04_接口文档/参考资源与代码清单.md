# 参考资源与代码清单

> 课题：**面向设备风险研判的标准知识工具化与 Harness 智能体系统**。
>
> 本科生研究内容：构建单智能体工具调用闭环,完成由设备工况输入到带条款依据结论输出的完整流程,并预留研判、审查、建议三类智能体协作的扩展接口。基础要求为单智能体,审查体仅为可选加分项。
>
> 技术指标(1)：完成原型系统在魔搭(ModelScope)创空间的部署,提供可公开访问的网页界面;界面须完整展示工具调用过程(每一步的推理、调用的工具、传入参数、返回结果)与最终结论的条款依据,支持外部人员输入设备工况自行验证。验收材料为魔搭部署链接与界面截图,详见 [技术指标验证方法](技术指标验证方法.md)。

# 一、开源工具调用数据集(用于补充通用能力)

## 1.1 为什么需要这些

本课题产出的是**垂直领域**数据(设备风险研判),数量在 200~500 条量级。直接用这个量微调,模型会出现两个问题:

- **灾难性遗忘**:学会了查腐蚀条款,但通用的工具调用能力退化
- **泛化不足**:换个没见过的工具就不会用了

解决办法是把垂域数据和开源通用工具调用数据**混合训练**。开源数据不用自己标,直接下载。

## 1.2 可用数据集

| 数据集 | 规模 | 特点 | 地址 |
|---|---|---|---|
| **ToolBench / ToolLLM** | 3451 个工具、16464 个 API、12657 条实例、37204 次真实 API 调用,平均推理轨迹 4.1 步 | 规模最大,含单工具和多工具场景,多工具又分同类别内和跨集合两种 | github.com/OpenBMB/ToolBench |
| **ToolAlpaca** | 3938 条实例,400+ 工具,50 个类别 | 规模适中,格式清晰,适合入门参考 | github.com/tangqiaoyu/ToolAlpaca |
| **API-Bank** | 2202 组对话、2211 个 API、覆盖 1008 个领域;另有 1.8K 对话的训练集 | 对话形式,含 API 检索环节 | 论文 arXiv:2304.08244 |

**ToolBench 的多步轨迹平均 4.1 步**,正好对应你们"多步轨迹调用 ≥3 次"的指标,可以直接作为标注时的参照。

## 1.3 许可证注意

ToolBench 的仓库对许可证的表述不完全一致(README 有 CC BY-NC 4.0 和 Apache 2.0 两种说法)。**CC BY-NC 是禁止商业用途的。**

本课题是教学与研究用途,使用没问题。但如果后续这套模型要交付给企业使用,**必须先把许可证核清楚**——这一条请写进结题报告的说明里,别留隐患。

## 1.4 混合比例:这是个可以做的实验

垂域数据和通用数据按什么比例混,没有标准答案,取决于模型规模和任务难度。这正好可以做成一组对照实验:

- 纯垂域(500条)
- 垂域 + 通用 1:1
- 垂域 + 通用 1:3
- 垂域 + 通用 1:5
- 纯通用(对照组)

评估指标就用课题技术指标里现成的:**条款引用准确率**和**工具调用解析成功率**。做出来是一张很干净的表,论文里可以直接用。

# 二、代码框架

## 2.1 Qwen-Agent(优先参考)

**github.com/QwenLM/Qwen-Agent**

阿里官方的 Agent 框架,基于 Qwen 系列模型,提供 Function Calling、Code Interpreter、RAG、MCP 集成等能力。架构上是由 LLM 和 Tool 两类原子组件组合成 Agent,通过继承 `BaseTool` 和 `Agent` 基类来定制。

**为什么优先参考这个**:项目的原型系统调用的就是 Qwen 模型,框架层面天然对齐。安装 `pip install -U qwen-agent`,需要 DashScope API Key 或自建的 OpenAI 兼容服务(vLLM、Ollama 都行)。

**怎么用**:看它的 `BaseTool` 怎么定义工具 schema,把我们的三个工具照着写。它的执行循环可以直接读源码理解,但**我们的 Harness 要自己实现**——因为课题指标要求护栏和轨迹留痕,现成框架不一定按我们的字段记录。

## 2.2 BFCL / Gorilla(评估参考)

**github.com/ShishirPatil/gorilla** → `berkeley-function-call-leaderboard/`

Berkeley 的函数调用评测基准,是目前事实上的标准。核心价值在于它的 **AST(抽象语法树)评估方法**——不真正执行工具,而是检查工具调用的结构是否正确,这样可以扩展到数千个函数。

**我们能直接用的**:
- `bfcl_eval/eval_checker/ast_eval/` —— 用来实现"工具调用解析成功率 ≥95%"这个指标,不用自己造轮子
- `bfcl_eval/model_handler/local_inference/qwen.py` 和 `qwen_fc.py` —— Qwen 模型在 Prompt 模式和 Function Calling 模式下的处理器,是很好的参考
- 它的 `decode_ast` 把模型的原始输出转成结构化的函数调用列表,格式是 `[{"func1": {"param1": "val1"}}]`

安装:`pip install bfcl-eval`(注意别装成 PyPI 上另一个不相关的 `bfcl` 包)。

## 2.3 LLaMA-Factory(微调用)

**github.com/hiyouga/LLaMA-Factory**

微调 Qwen 系列的主流工具,支持全参数、LoRA、QLoRA、DoRA。数据集支持 **alpaca** 和 **sharegpt** 两种格式。

**一个已知的坑**:多轮 function call 数据往 sharegpt 格式里塞的时候,格式对不齐——sharegpt 要求 observation 之后必须跟一个 gpt 回复,但 agent 训练时 observation 之后往往是"对下一步的规划",不是最终回答。社区里这个问题被反复提过,没有官方标准答案。

**所以我们的 schema 设计要提前考虑这一点**:`trajectories.jsonl` 里每个 step 的 `thought` 字段,在转 sharegpt 时就充当那个"gpt 回复"。转换脚本 `convert_to_sharegpt.py` 由负责工具封装的同学写,**第 8 周之前必须写完并验证**,否则最后拿到 200 条数据却灌不进训练框架。

Qwen 官方也有 LLaMA-Factory 的中文使用文档:qwen.readthedocs.io 的 training/llama_factory 章节。

# 三、论文清单

## 3.1 必读(理解课题在做什么)

| 论文 | 为什么读 |
|---|---|
| **ReAct: Synergizing Reasoning and Acting in Language Models**(arXiv:2210.03629) | 我们 Harness 的 thought/tool/args/result 循环就是 ReAct 范式。**第一周必读** |
| **ToolLLM: Facilitating LLMs to Master 16000+ Real-world APIs**(arXiv:2307.16789) | 大规模工具调用数据是怎么造出来的,含 DFSDT 方法 |
| **API-Bank: A Comprehensive Benchmark for Tool-Augmented LLMs**(arXiv:2304.08244) | 里面有个结论对我们特别重要:**构建多样化、高质量的训练数据是提升模型工具使用能力的有效路径**,而且严格遵循 API 文档对模型来说是个显著挑战 |
| **The Berkeley Function Calling Leaderboard (BFCL)**(ICML 2025) | 评测方法。它的结论也值得注意:**当前顶尖模型在单轮调用上表现很好,但在记忆、动态决策和长程推理上仍有明显短板** |

## 3.2 选读

- **API-BLEND: A Comprehensive Corpora for Training and Benchmarking API LLMs**(arXiv:2402.15491)—— 各个工具调用数据集的横向对比,选混合数据时可以参考
- **ToolPlanner**(arXiv:2409.14826)—— 多粒度指令 + 路径规划,里面提到现有数据集的一个通病:指令写得太详细,和真实用户的使用习惯不符。这一点对我们标注 `input.question` 时有直接启发——**别把问题写得像标准答案**

## 3.3 领域侧论文(自己检索)

通过学校的 CNKI/万方权限检索,重点找这几类:

| 检索关键词 | 找什么 |
|---|---|
| 常减压装置 塔顶 腐蚀 失效分析 | 失效案例,尤其是含"材质-介质-工况-机理"对照表的 |
| RBI 风险评估 炼化装置 | 风险分级的实际应用,可以校对我们的映射表 |
| 损伤机理 识别 承压设备 | 机理判据的归纳性综述 |
| 腐蚀速率 预测 常压塔 | 定量判据,可以补充 `applicable_conditions` |

**重点找带表格的论文。** 综述类论文里的"损伤机理汇总表""材质适用性对照表"是最容易结构化的,一张表往往能抽出十几条记录。找到好表格的同学在群里共享,别重复劳动。

**注意**:论文里的数据可以作为参考和交叉验证,但 `clauses.jsonl` 的 `source` **只能引用标准条款,不能引用论文**。论文没有条款号,不满足"可回溯至具体标准条款"的要求。

# 四、动手顺序建议

第 1 周不要急着写代码,按这个顺序过一遍:

1. 读 ReAct 论文,理解 thought-action-observation 循环
2. 跑通 `harness_skeleton/harness.py`(用 mock 工具,不接大模型)
3. 下载 ToolAlpaca 的 `train_data.json`,看它的轨迹长什么样
4. 看 Qwen-Agent 里 `BaseTool` 的定义方式
5. 再回来看我们的三个工具接口规范,这时候应该就看懂了

跳过 1~4 直接写代码的,大概率会写出一个"能跑但不符合规格"的东西,第 8 周返工。
