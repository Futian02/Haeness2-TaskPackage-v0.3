# 护栏测试用例格式说明（v0.3）

两个文件都由学生自己写，放进 `05_提交区/`：

| 文件 | 内容 | 数量要求 | 判定 |
|---|---|---|---|
| `guardrail_cases.jsonl` | 应被拦截的异常调用 | 四类各 ≥3 条，共 ≥12 条 | 全部拦截才算拦截率 100% |
| `normal_cases.jsonl` | 应正常放行的调用 | ≥30 条 | 一条被拦即不达标 |

这两个文件不计入 200 条轨迹配额，格式也和 `trajectories.jsonl` 不同，不要混放。本目录的两个 `_模板.jsonl` 各给了示范行，照格式写，内容要自己构造，不要只改个数字。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `case_id` | 是 | 唯一编号。建议 GR-UT / GR-MP / GR-OD / GR-BF 加序号，正常用例用 NC 加序号 |
| `category` | 是 | `unknown_tool` 工具名错误 / `missing_param` 参数缺失 / `out_of_domain` 超出适用范围 / `bad_format` 格式不合规 / `normal` 正常调用 |
| `description` | 是 | 一句话说明这条测什么 |
| `call` | 是 | `{"tool": 工具名, "args": {参数}}`，就是模型会发出的那次调用 |
| `mock_response` | 否 | 想测「工具返回格式不合规」时，在这里写一份故意写坏的返回，测试脚本会用它替换工具的真实返回 |
| `expect` | 是 | 异常用例填 `blocked`，正常用例填 `pass` |

## 各类怎么算拦住

- `unknown_tool`、`missing_param`、`bad_format`：护栏抛出同类 `GuardrailError` 才算拦住。参数值不在枚举表、参数类型不对、多了未知参数，在骨架里都归 `bad_format`。
- `out_of_domain`：两种情况都算拦住。一是工具自己返回 `in_domain=false` 且 `result` 为空；二是工具返回了 `in_domain=false` 却带着结论，被护栏按 `out_of_domain` 拦下（这种用 `mock_response` 构造）。
- `normal`：没有抛出任何 `GuardrailError` 就算放行。返回 `not_found` 也算放行，那是查不到，不是被拦。

## 怎么跑

在任务包根目录运行：

```
python 04_接口文档/harness_skeleton/run_guardrail_tests.py
```

默认读取 `05_提交区/guardrail_cases.jsonl` 和 `05_提交区/normal_cases.jsonl`，输出每条结果、各类拦截率和误拦数，并把报告写到 `05_提交区/guardrail_report.md`，这份报告就是技术指标(3)护栏部分的验收材料。退出码 0 表示全部符合预期。

构造用例时注意多样性：别名、全角字符、类型写错（温度写成 "110℃" 字符串）、数组写成逗号字符串、`top_k` 超上限等，都是真实模型常犯的错。
