# 工具接口规范

> 课题：**面向设备风险研判的标准知识工具化与 Harness 智能体系统**。
>
> 本科生研究内容：构建单智能体工具调用闭环,完成由设备工况输入到带条款依据结论输出的完整流程,并预留研判、审查、建议三类智能体协作的扩展接口。基础要求为单智能体,审查体仅为可选加分项。
>
> 技术指标(1)：完成原型系统在魔搭(ModelScope)创空间的部署,提供可公开访问的网页界面;界面须完整展示工具调用过程(每一步的推理、调用的工具、传入参数、返回结果)与最终结论的条款依据,支持外部人员输入设备工况自行验证。验收材料为魔搭部署链接与界面截图,详见 [技术指标验证方法](技术指标验证方法.md)。

> 与根目录 [README.md](../README.md) 配套使用，三个工具的定义以本文件为准。损伤机理返回的内容字段依据 GB/T 30579—2022 第 4.4 条及各损伤模式子条款采用八段式，损伤模式名称与标准原文一致；“常见错误”和文末“补充说明”为教学提示。

> **v0.3**：三个工具以本文件为唯一口径，README 不再重复工具定义；示例中的介质使用 enums.json 规范值；风险等级示例与 GB/T 26610.3-2014 图1 一致。

# 第二部分 · 三个工具(核心,必须严格实现)

Harness 能调用的工具**只有以下三个**,不得增删,不得改名,不得改参数名。

## 2.1 工具总览

| 工具名 | 回答什么问题 | 对应专家动作 |
|---|---|---|
| `damage_mechanism_query` | 这个材质+介质+工况下,可能是哪些损伤机理? | 第 4 步:识别与鉴别 |
| `rbi_lookup` | 这个机理在这台设备上,风险等级多高?多久该检验一次? | 第 5 步:判严重性 |
| `standard_clause_search` | 关键词/现象 → 命中哪些条款? | 兜底检索 |

## 2.2 `damage_mechanism_query` — 损伤机理识别与鉴别

**用途**:输入设备工况,返回可能的损伤机理清单,并指出如何区分它们。

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `material` | string | 是 | 材质,取值见 `enums.json`。如 "碳钢"、"20#"、"12Cr5Mo"、"06Cr19Ni10"、"S22053" |
| `medium` | `array[string]` | 是 | 介质列表。如 `["湿硫化氢","氯化氢","氯化铵"]`。写 enums.json 登记过的别名（如 `湿H2S`、`HCl`）也能通过，护栏会先归一化成规范值再调用工具 |
| `temperature_c` | number | 否 | 操作温度 ℃ |
| `equipment_type` | string | 否 | 塔/换热器/管道/容器/加热炉/储罐 |
| `evidence` | object | 否 | 现场证据,见下 |

`evidence` 子字段(**这是本工具的关键设计**):

| 字段 | 类型 | 说明 |
|---|---|---|
| `ph` | number | 塔顶水/工艺水 pH |
| `cl_ppm` | number | 氯离子含量 mg/L |
| `fe_ppm` | number | 铁离子含量 mg/L |
| `h2s_ppm` | number | 硫化氢含量 |
| `wall_thinning` | boolean | 测厚是否发现减薄 |
| `crack_found` | boolean | 是否发现裂纹 |

**`mechanisms` 中每个条目的八个内容字段**

| 字段 | 类型 | 对应 GB/T 30579—2022 子条款内容 |
|---|---|---|
| `description` | `string` | 损伤描述及损伤机理 |
| `morphology` | `array[string]` | 损伤形态 |
| `affected_materials` | `array[string]` | 受影响的材料 |
| `influencing_factors` | `array[string]` | 主要影响因素 |
| `susceptible_locations` | `array[string]` | 易发生的装置或设备 |
| `prevention` | `array[string]` | 主要预防措施 |
| `detection_methods` | `array[string]` | 检测或监测方法 |
| `related_damages` | `array[string]` | 相关或伴随的其他损伤 |

`name`、`clause_id`、`match_level` 保持原有定义，不计入上述八个内容字段。

**返回**

```json
{
  "status": "ok",
  "in_domain": true,
  "result": {
    "mechanisms": [
      {
        "name": "盐酸腐蚀",
        "clause_id": "GBT30579-2022-X.X.X",
        "description": "损伤描述及损伤机理",
        "morphology": ["全面腐蚀", "局部腐蚀"],
        "affected_materials": ["碳钢", "低合金钢", "300系列不锈钢", "400系列不锈钢"],
        "influencing_factors": ["pH值", "氯离子浓度", "温度"],
        "susceptible_locations": ["常压塔塔顶系统", "减压塔塔顶真空喷射器和冷凝设备"],
        "prevention": ["注水", "注中和剂", "注缓蚀剂"],
        "detection_methods": ["定点测厚", "超声扫查"],
        "related_damages": ["氯化铵腐蚀", "氯化物应力腐蚀开裂"],
        "match_level": "high"
      }
    ],
    "discriminator": "盐酸腐蚀与氯化铵腐蚀的区分依据:前者发生在露点附近且pH明显偏低;后者发生在铵盐结晶温度以上、注水点上游,常伴压降上升。建议补充:塔顶水pH、注水点位置、系统压降趋势。",
    "excluded": [
      {"name": "湿硫化氢破坏", "reason": "未提供H2S数据,无法判定"}
    ]
  },
  "source": [{"clause_id": "...", "standard_code": "GB/T 30579-2022", "clause_no": "X.X.X", "page": 27}],
  "message": ""
}
```

**设计要点(请理解后再实现)**

- `mechanisms` 的内容字段采用**固定八段式**，对应 GB/T 30579—2022 第 4.4 条列出的八个方面及各损伤模式的实际子条款，例如盐酸腐蚀的第 5.1.1～5.1.8 条。字段名及含义见上表，**不得自行增减或改名**；`description` 为字符串，其余七个内容字段均为字符串数组。
- `affected_materials` 是**材质适用性判定的根据**，应从“受影响的材料”子条款提取，并与入参 `material` 对照。
- `related_damages` 应从“相关或伴随的其他损伤”子条款提取，可用于**串联相关机理、生成多步轨迹**；列表中的损伤模式名称应保持标准原文写法。
- `discriminator` 字段是本工具最有价值的部分。真实专家不是"列出所有可能",而是**用现场证据把候选项一个个排除掉**。当 `evidence` 信息不足以区分多个机理时,这个字段要明确说出"还需要看什么数据"。
- `excluded` 记录被排除的机理及排除理由。**排除本身就是有价值的推理,必须记录。**

**损伤模式命名提醒**：损伤模式名称必须使用 GB/T 30579—2022 原文叫法，例如“湿硫化氢破坏”（非“湿硫化氢损伤”）、“氯化铵腐蚀”（非“氯化铵垢下腐蚀”）、“高温硫化物腐蚀”（非“高温硫腐蚀”）。自行改名会导致条款检索失败。引用第 5.21、5.22 条时，还应保留“无氢气环境”或“氢气环境”等条款名称限定。

### 常见错误（补充提示）

不要把 `medium` 写成逗号分隔的字符串，也不要把 `evidence` 的子字段移到顶层；`ph` 等数值字段用 number，`wall_thinning`、`crack_found` 用 boolean，未提供现场证据不等同于 `false`。不要把可选参数改成必填，或改写八段式字段名、漏掉 `discriminator` 和 `excluded`；证据不足时应说明还需要哪些数据，不能凭缺失值给出确定判断。返回示例中的 `X.X.X`、`...` 是占位符，实际实现时应填入真实条款出处。

## 2.3 `rbi_lookup` — 风险等级与检验周期

**用途**:输入设备信息与已识别的损伤机理,返回风险等级、检验周期建议、推荐检验方法。

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `equipment_type` | string | 是 | 设备类型 |
| `material` | string | 是 | 材质 |
| `mechanism` | string | 否 | 已识别的损伤机理名称 |
| `medium` | `array[string]` | 否 | 介质 |
| `temperature_c` | number | 否 | 温度 |
| `pressure_mpa` | number | 否 | 压力 |
| `service_years` | number | 否 | 已投用年限 |

**返回 `result`**

```json
{
  "likelihood": "3",
  "consequence": "D",
  "risk_level": "中高风险",
  "risk_level_unified": "L3",
  "inspection_interval_year": 3,
  "inspection_methods": ["定点测厚", "湿荧光磁粉"],
  "basis_note": "按GB/T 26610.3-2014图1,失效可能性等级3、后果等级D为中高风险,统一等级L3;检验周期另有条款依据"
}
```

**注意 `risk_level_unified`**:不同标准体系的风险分级方式不同(GB/T 26610 与 API 581 不一致,企业内部还有 7×8 矩阵)。所有返回必须同时给出**原始等级**和**映射后的统一等级**(L1~L5)。映射表见 `04_接口文档/risk_level_mapping.xlsx`（v0.3 随任务包发放），**不得自行修改**。GB/T 26610.3-2014 的原始等级只有低、中、中高、高四档，分别对应 L1～L4；其他 GB/T 26610 部分若用同样的四档用语，按用语对应。本任务包内的标准不会映射到 L5。

### 常见错误（补充提示）

不要漏掉必填的 `equipment_type`、`material`，也不要把可选的 `mechanism` 等参数改成必填。`medium` 是数组，`temperature_c`、`pressure_mpa`、`service_years` 是数值；不要将带单位的文字直接作为数值参数传入。不要混用 `risk_level` 与 `risk_level_unified`，统一等级必须查给定映射表，不能自行猜测或修改映射；示例中的等级和检验周期也不能硬编码成所有查询的答案。GB/T 26610.3-2014 本身不给检验周期，返回周期时 `source` 必须带上周期所依据的条款（如 GB/T 26610.2-2022 或 TSG 21-2016 的具体条款）；找不到依据就填 `null`，不要凭经验给数。上面的 JSON 仅是 `result`，实际返回仍要套用第 2.5 节的统一外壳，不能用 `basis_note` 代替 `source`。

## 2.4 `standard_clause_search` — 条款关键词检索

**用途**:兜底检索。当前两个工具的结构化查询无法覆盖时,按关键词或现象描述查条款。

**入参**

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `keyword` | string | 是 | 关键词或现象描述 |
| `knowledge_type` | string | 否 | `rbi` / `damage_mechanism` |
| `top_k` | number | 否 | 默认 5,上限 20 |

**返回 `result`**

```json
{
  "hits": [
    {"clause_id": "...", "title": "...", "snippet": "条款要点摘录,≤200字", "score": 0.87}
  ]
}
```

### 常见错误（补充提示）

不要漏掉必填的 `keyword`，也不要把可选的 `knowledge_type` 改成必填；提供 `knowledge_type` 时只能使用 `rbi` 或 `damage_mechanism`。不要遗漏 `top_k` 默认 5、上限 20 的限制，或把 `snippet` 写成超过 200 字的长文。返回内容应保留 `result.hits` 数组及每项的 `clause_id`、`title`、`snippet`、`score`，不能直接返回列表或自行改名。上面的 JSON 仅是 `result`，命中项中的 `clause_id` 不能替代统一外壳的 `source`；不要把示例中的 `...` 当作真实条款号返回。

## 2.5 三个工具共用的返回外壳(不可改)

```json
{
  "status": "ok | out_of_domain | not_found | error",
  "in_domain": true,
  "result": {},
  "source": [],
  "message": ""
}
```

- `in_domain` 是**适用性标识**。查询条件超出条款覆盖范围时必须为 `false`,`result` 置空,并在 `message` 里说明超出了什么。
- **任何 `status="ok"` 的返回,`source` 数组不得为空。** 这是硬性红线。

---

### 统一返回外壳补充说明

三个工具均使用第 2.5 节的五个顶层字段：`status`、`in_domain`、`result`、`source`、`message`。`rbi_lookup` 和 `standard_clause_search` 的示例只展示 `result` 内部内容，实际返回时仍需包含完整外壳。示例中 `status` 的竖线表示可选值，实际填写其中一个值，不要将 `ok | out_of_domain | not_found | error` 整串作为状态返回。

查询条件超出条款覆盖范围时，按原文将 `in_domain` 设为 `false`、`result` 置空，并在 `message` 中说明超出了什么。外壳示例中的空 `source` 仅用于展示结构，不能照搬到成功返回中；`message`、`basis_note` 或结果中的条款号都不能代替 `source` 数组。

**硬性要求：任何 `status="ok"` 的返回，`source` 数组不得为空。三个工具一律适用。**
