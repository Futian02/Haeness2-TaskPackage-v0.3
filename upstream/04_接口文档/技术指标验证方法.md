# 技术指标验证方法

> 课题：**面向设备风险研判的标准知识工具化与 Harness 智能体系统**。
>
> 本科生研究内容：构建单智能体工具调用闭环,完成由设备工况输入到带条款依据结论输出的完整流程,并预留研判、审查、建议三类智能体协作的扩展接口。基础要求为单智能体,审查体仅为可选加分项。

> 放在 `04_接口文档/`。说明四项技术指标各自怎么验、谁来验、什么时候验、交什么材料。
> 学生按此准备验收材料,指导教师与评审按此核查。

---

## 总览

| 指标 | 验证方式 | 自动/人工 | 何时做 |
|---|---|---|---|
| (1) 魔搭部署与过程可视 | 打开链接实操 | 人工,可现场演示 | 第 10 周 |
| (2) 条款引用准确率 ≥95% | 随机抽样 + 交叉核对 | 人工 | 第 5 周试核 + 第 10 周正式核 |
| (3) 解析成功率 ≥95%、轨迹完整率 100%、护栏拦截率 100% | 批量跑测试集 | 自动 | 第 7 周(护栏)+ 第 9 周(解析) |
| (4) 数据集条数、格式、可回溯 | `validate.py` | 全自动 | 每周五 + 第 10 周终验 |

## 指标(1)· 魔搭部署与过程可视

**要求**:完成原型系统在魔搭(ModelScope)创空间的部署,提供可公开访问的网页界面;界面须完整展示工具调用过程(每一步的推理、调用的工具、传入参数、返回结果)与最终结论的条款依据,支持外部人员输入设备工况自行验证。

### 怎么做

用 Gradio 搭界面,部署到 ModelScope 创空间(Studio),免费且支持公开访问。

界面三块:

**输入区** — 设备类型、材质、介质(多选)、操作温度、现场证据(pH、氯离子、铁离子、是否减薄、是否发现裂纹)、问题描述

**过程区(核心)** — 点击研判后逐步展示每一轮:第几步 / 本步推理 / 调用的工具 / 传入参数 / 工具返回 / 观察结论。被护栏拦截的调用也要显示,并标明拦截类型。

**结论区** — 最终结论 + 依据条款列表,每条条款可展开查看标准号、条款号、页码与原文摘录。

### 为什么过程区比结论区重要

评审最关心的问题是"你怎么证明模型没有编造条款"。一堆指标数字说服力有限,但让评审看到"模型第 1 步查了什么、返回了什么、第 2 步为什么要再查一次",这个过程本身就是证明。

技术上不难:`harness.py` 已经把 `Trajectory` 结构化了,Gradio 层只是把它渲染出来。

### 验收材料

- 可公开访问的魔搭链接
- 界面截图(至少覆盖:单步查询、多步查询、护栏拦截、超范围拒答四种情形)
- 现场演示:由评审自行输入一组工况,当场查看过程与依据

## 指标(2)· 条款引用准确率 ≥95%

**要求**:抽样核对不少于 50 条,条款引用准确率不低于 95%。

这项**必须人工**。机器只能查条款号存不存在,查不了引用得对不对。

### 抽样规则

用脚本从 `clauses.jsonl` 随机抽 50 条,**不许人工挑选**。抽样脚本与随机种子记录在核对报告里,保证可复现。

### 核对三件事

对着标准原文 PDF,逐条核:

| 核对项 | 常见错误 |
|---|---|
| 条款号与页码是否正确 | 条款号写成上一级(写 5.1 实际内容是 5.1.4) |
| `content_raw` 是否为原文 | 被润色改写,或掺入了自己的理解 |
| `applicable_conditions` 是否超出原文范围 | **最高发**:原文写"碳钢",填成"碳钢及低合金钢";原文无温度限制,自行加了区间 |

### 交叉核对,不许自核

A 抽到的条款交给 B 核,B 的交给 C 核,依次轮转。自己核自己等于没核。

### 判定

50 条中不通过 ≤2 条为达标(准确率 ≥96%);不通过 3 条即为 94%,不达标,须全面返工后重抽。

### 时间安排

**第 5 周先试核 20 条。** 这一步不能省——如果那时准确率只有 70%,还有五周可以返工;第 10 周才发现就来不及了。试核结果不计入正式验收,只用于暴露系统性错误。

### 交什么

核对报告表,每行包含:抽样序号、条款 ID、抽取人、核对人、是否通过、不通过原因、复核意见。

## 指标(3)· Harness 运行质量

**要求**:支持 ≥5 轮连续工具调用;工具调用解析成功率 ≥95%;全过程轨迹记录完整率 100%;四类异常各 ≥3 个测试用例,护栏拦截率 100% 且不误拦正常调用。

### 3.1 连续调用轮次

`harness.py` 的 `MAX_ROUNDS` 已设为 8。构造一个需要 5 轮以上才能完成的测试任务跑通即可,截图存证。

### 3.2 轨迹完整率 100%

由 `harness.py` 的设计保证:被护栏拦截的调用和执行异常的调用都会写入 `Trajectory` 的运行日志(`to_dict()`),不会因为报错就丢记录。数据集 `trajectories.jsonl` 用 `to_record()` 导出,只收不含拦截步骤的轨迹,两者用途不同。

验证方法:跑 100 次调用(含故意触发异常的),统计 `len(traj.steps)` 与实际发起的调用次数是否相等。相等即 100%。

### 3.3 护栏拦截率 100% 且不误拦

**这一项有两半,只做前一半是不够的。**

- **拦截率**:四类异常(工具名错误、参数缺失、超出适用范围、输出格式不合规)各构造 ≥3 个用例,共 ≥12 条,存于 `guardrail_cases.jsonl`。全部应被拦截,漏拦一条即不达标。
- **不误拦**:另外准备 ≥30 条**正常调用**用例,全部应顺利通过。误拦一条即不达标。

很多人只测拦截、不测误拦,结果护栏写得过严,正常查询也被挡,系统等于不可用。两半都要交。

用例格式和模板见 `04_接口文档/templates/用例格式说明.md`。写好后运行 `python 04_接口文档/harness_skeleton/run_guardrail_tests.py`,脚本逐条跑护栏,输出各类拦截率与误拦数,并写出 `05_提交区/guardrail_report.md` 作为验收材料。

### 3.4 解析成功率 ≥95%

**这项必须真的跑大模型**,前面几项都是静态检查,这项不是。

做法:准备 100 组测试输入(设备工况 + 问题),接入 Qwen 让 Harness 完整跑一遍,统计模型输出能被正确解析成合法工具调用的比例。

**注意"解析成功"的定义**:指模型输出的格式合法、工具名存在、参数结构正确 —— **不是指答案对不对**。答案对不对是指标(2)的事。

可直接复用 BFCL(Berkeley Function Calling Leaderboard)的 AST 评估方法,不必自己造轮子。`pip install bfcl-eval`,用其中的 `eval_checker/ast_eval/`。

100 组中成功解析 ≥95 组为达标。

## 指标(4)· 数据集质量

**要求**:轨迹 ≥200 条(多步 ≥40 条),格式校验通过率 100%,每条轨迹结论均可回溯至具体标准条款。

这项**全自动**,`validate.py` 一次跑完。

### 脚本查什么

| 检查项 | 说明 |
|---|---|
| 字段完整性与类型 | 按 `schema/` 下三个 JSON Schema 校验 |
| 枚举值合法性 | 材质、介质、设备类型是否在 `enums.json` 白名单内 |
| **`basis` 可回溯性** | `final_answer.basis` 中每个 `clause_id` 必须在 `clauses.jsonl` 中真实存在 |
| `clause_id` 主键唯一 | 不得重复 |
| `task_type` 一致性 | 调用 ≥3 次必须为 `multi_step`,否则为 `single_step` |
| 条款总数与覆盖 | ≥300 条,损伤机理与 RBI 两类都有(`--final`) |
| 轨迹总条数 | ≥200(`--final`) |
| 多步轨迹条数 | `task_type=multi_step` ≥40(`--final`) |
| 特殊轨迹配额 | 三类各 ≥15 条(依 `special_type` 字段统计,`--final`) |
| `source` 非空 | `status=ok` 的工具返回必须带出处 |

### 最硬的一项

**`basis` 可回溯性**是这套验收里唯一能自动识破"编造出处"的检查。学生编一个看起来很像的条款号,肉眼看不出来,脚本一比对就露馅。

### 怎么跑

在任务包根目录执行:

```
python 04_接口文档/validate.py
```

默认检查 `05_提交区/` 下的 `clauses.jsonl` 与 `trajectories.jsonl`。

每周五用自查模式,数量只报进度;第 10 周用终验模式 `python 04_接口文档/validate.py --final`,数量不达标也判失败。

退出码:`0` 通过 / `1` 有记录不合规(`--final` 下还包括数量不达标) / `2` 依赖、Schema、文件读取或空文件问题。

依赖:`python -m pip install "jsonschema>=4.18,<5"`

### 纪律

**每周五全员跑一次**,不通过的当周修完。攒到第 10 周一次性修,一定来不及。

### 脚本查不了什么

`validate.py` 只查格式与引用关系,**不查内容真实性**:

- 条款抄得对不对 → 指标(2)人工抽样
- 工具返回是不是真实调用的结果 → 抽查比对
- 200 条是不是同一模板换参数 → 人工看多样性

**格式全过 ≠ 数据合格。** 两道关都要过。
