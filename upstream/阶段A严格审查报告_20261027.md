## 二、逐项审查记录

### 审查 1：拦截类型是否名副其实（36 条异常用例）

逐条实跑，对比 `category` 与实际抛出的 `GuardrailError.kind`。

**结果：36/36 全部精确匹配，无 MISMATCH。**

这是关键项——`run_guardrail_tests.py` 的 `judge()` 要求 `blocked and kind == case["category"]`，只"被拦了"但类型不对照样判不符合预期。

### 审查 2：护栏是否「过严」

用正常用例的 13 个近邻变体做压力测试：别名写法、evidence 全字段、空 evidence、`temperature_c=0`、负温度、`service_years=0`、超大 service_years、`top_k=20` 边界、`top_k=0`、keyword 带空格、单元素 medium、省略 mechanism、`ph=0`。

**结果：13/13 全部放行，无误伤。** 护栏不过严。

### 审查 3：正常用例的「放行质量」——发现质量不足

初版 57 条里 **4 条返回 `not_found`**：材质别名 SS、rbi_lookup 只给必填两项、检索「盐垢结晶」、检索「塔顶结盐 压降上升」。

这 4 条**确实是放行**（`用例格式说明`：「返回 not_found 也算放行，那是查不到，不是被拦」），但作为"证明护栏没写得过严"的证据，证明力偏弱——护栏放行了一个没给出结果的调用。

**处置**：全部替换为实测返回 `ok` 的等价用例，并补足条数：

| 原用例 | 替换为 |
|---|---|
| 材质别名 SS（不锈钢） | 材质别名 **S30408**（= 06Cr19Ni10）+ 循环水 |
| rbi_lookup 只给必填两项 | rbi_lookup 给必填两项 + **mechanism=盐酸腐蚀** |
| 检索 盐垢结晶 | 检索 **氯化铵** |
| 检索 塔顶结盐 压降上升 | 检索 **塔顶 腐蚀**、检索 **湿硫化氢 裂纹 检测** |

另补 3 条牌号别名用例（S30408、20#、Q245R钢板）。

**结果：60 条全部返回 `ok`。**

### 审查 4：我上一轮修的 bug 有无副作用——发现真缺陷

我上一轮给 `rbi_lookup` 加了「机理名必须在库中真实存在」的校验，防止对臆造机理给结论。审查时测边界：

```
'高温硫化物腐蚀(无氢气环境)'  → ok      半角括号，正常
'高温硫化物腐蚀（无氢气环境）' → not_found  ← 全角括号，误判
'475℃脆化'                   → ok
' σ相脆化 '                  → ok      首尾空格已处理
```

**缺陷**：模型写全角括号时指同一条款，却判为查不到。

**修复**：新增 `_canon_mechanism()`，归一化首尾空白与全角/半角（括号、逗号、冒号、分号、全角空格、长横线）。判定与 DF 归类**两处都用归一化后的名字**。

修复后复测：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| 高温硫化物腐蚀（无氢气环境） | not_found | **ok** |
| 库中 82 个机理名 | 82/82 | **82/82**（无回归） |
| 超导脆化 / 不存在的机理XYZ | not_found | **not_found**（臆造仍被拒） |

## 四、审查沉淀的纪律

1. **异常用例判分看 `kind` 精确相等**，不是"被拦了"就算——`judge()` 的实际逻辑是 `blocked and kind == case["category"]`。
2. **正常用例要选实测返回 `ok` 的**。`not_found` 虽算放行，但证明力弱于真给出结果的调用。
3. **改工具行为时要测边界变体**。全角括号这个缺陷是"审查输入变体"才暴露的，常规用例扫描测不出来。
4. **「防臆造」的校验必须配「容错」**，否则会把合法的书写变体一起拒掉。
5. **参数签名相同 ≠ 模板雷同**，要看取值组合是否唯一。
