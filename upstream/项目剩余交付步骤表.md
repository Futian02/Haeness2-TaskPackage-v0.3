## 四、开始时机建议

| 情形 | 建议 |
|---|---|
| 想**最快拿到一个完整可交付包** | 先做 A（3~5 h）→ 再做 B（14~20 h）→ 然后 D（6.5~9.5 h）→ 最后 C 和 E。**最短路径约 25~35 h**，因为 C 依赖外部模型，放最后不影响交付完整度。 |
| 想**并行压到最短** | 今天开 A + D1（Gradio 界面不依赖轨迹）；同时开 B1 场景设计。B2 开始后 C1 也可并行。**2 人并行约 18~25 h**。 |
| 只求**先交一批像样的** | 只做 A1+A2+A3 + B1+B2（40 条多步），约 8~12 h，即可交出一份含护栏报告和多步轨迹的中间版本。README 第 7 周表也是这个顺序：先 40 条多步，过了才准刷单步。 |
| 需要**人工介入的** | E4 签字、抽样核对报告的终稿确认、魔搭账号注册——这三项必须留出你本人的时间窗口。 |

**三个风险点提前告知**：
1. **C 阶段需要 Qwen API 额度**，若没准备好会卡住；且 bfcl-eval 依赖安装可能有兼容问题。
2. **D 阶段需要魔搭账号与外网**，部署本身不可控。
3. **B2 的 40 条多步是验收顺序上的硬门槛**——README 第 7 周表写明「先交 40 条多步，过了才准刷单步」，所以 B2 必须先达标，不能一上来铺 200 条。
