# 第一部分 · 你们在做什么(必读)

## 1.1 一个真实场景

某炼油厂常减压装置,凌晨三点,塔顶回流罐的水样分析报出铁离子超标。

值班工程师要在半小时内回答三个问题:**这是什么原因造成的?严不严重?现在该做什么?**

他的实际动作是这样的:

1. 先怀疑数据本身——取样点对不对?仪表最近校过没有?
2. 查装置台账——这个部位是什么材质、上次检验是什么结论、投用多少年了
3. 看工况——塔顶温度离水露点还有多远?注水量、中和剂加注量正常吗?最近换原油了吗?
4. **翻标准**——这个材质 + 这个介质 + 这个温度,可能的损伤机理有哪几个?怎么把它们区分开?
5. 判严重性——这个机理在 RBI 体系里是什么风险等级?要不要提前安排检验?
6. 定检验手段——如果怀疑是裂纹,该做磁粉还是 TOFD?如果是减薄,该定点测厚还是扫查?
7. 出结论——立即措施 + 中期措施,**每一条都要写清楚依据是哪本标准的哪一条**

第 7 步的"写清楚依据"是整件事的要害。工程师不能说"我觉得是盐酸腐蚀",他必须说"依据 GB/T 30579 第 X 条,该材质在含 HCl 湿环境下适用盐酸腐蚀机理判据"。因为这份判断要签字,要进检验计划,出了事要追责。

## 1.2 我们要让机器学会的,就是第 4~7 步

**本科生研究内容**:构建单智能体工具调用闭环,完成由设备工况输入到带条款依据结论输出的完整流程,并预留研判、审查、建议三类智能体协作的扩展接口。

大模型直接回答这类问题,有两个致命毛病:

- **编条款**。它会说得头头是道,然后引用一个根本不存在的条款号。
- **过度归因**。看到"腐蚀"两个字就往腐蚀机理上靠,不会说"数据不够,判不了"。

解决办法不是换更大的模型,而是**在模型外面套一个运行框架**——不让它凭记忆答,而是逼它去调用工具查真实的条款库,查到什么答什么,查不到就说查不到。这个框架就叫 **Harness**。

所以本课题的完整逻辑是:

```
标准条款(非结构化文本)
   ↓ 结构化抽取
条款库(程序可读)
   ↓ 封装
三个工具(可被大模型调用)
   ↓ Harness 框架编排
单智能体完成研判,全程留痕
   ↓ 批量运行
工具调用轨迹数据集 → 用于微调模型
```

## 1.3 什么是 Harness(重要,别跳过)

很多人以为"让大模型用工具"就是给它一个 API。不是的。Harness 是模型外面那一整套**约束和保障机制**,包含四个部分:

| 组成 | 作用 | 没有它会怎样 |
|---|---|---|
| **工具注册** | 声明有哪些工具、每个工具收什么参数 | 模型会调用不存在的工具 |
| **执行循环** | 让模型能连续多轮调用,而不是只调一次 | 复杂问题一步答不完 |
| **安全护栏** | 拦截参数缺失、超出适用范围等异常 | 模型会硬答超纲问题 |
| **轨迹留痕** | 完整记录每一步的思考、调用、返回 | 出了错无法追责,也拿不到训练数据 |

**"模型的可靠性主要取决于 Harness 而不是模型本身"——这是本课题的核心论点,你们做的所有工作都是在验证它。**

## 1.4 你们的产出会被用到哪里

不是交完作业就结束。你们产出的条款库和轨迹数据,会和团队另一条线(装置专属知识,由研究生负责)的数据**合并**,共同构成模型微调的训练集。

这就是为什么本文档对字段格式的要求近乎苛刻:**两套数据的字段必须逐字一致,否则合并时会全部作废。** 请不要自行"优化"字段名。

## 1.5 你们不会拿到的东西

企业的装置专属资料(腐蚀控制技术手册、设备台账、真实事故案例)涉及商业保密,不对本课题开放。

所以你们做的是**通用标准知识**这一半:RBI 标准 + 损伤机理标准。装置专属的那一半由另一条线完成。两半各自独立,最后合并。

**请不要在网上搜索并使用任何企业内部资料。**

# 第二部分 · 三个工具(核心,必须严格实现)

Harness 能调用的工具**只有以下三个**,不得增删,不得改名,不得改参数名。

## 2.1 工具总览

| 工具名 | 回答什么问题 | 对应专家动作 |
|---|---|---|
| `damage_mechanism_query` | 这个材质+介质+工况下,可能是哪些损伤机理? | 第 4 步:识别与鉴别 |
| `rbi_lookup` | 这个机理在这台设备上,风险等级多高?多久该检验一次? | 第 5 步:判严重性 |
| `standard_clause_search` | 关键词/现象 → 命中哪些条款? | 兜底检索 |

## 2.2~2.4 三个工具的详细定义

入参、返回结构、设计要点和常见错误全部见 **`04_接口文档/工具接口规范.md`**,README 不再重复抄写,避免两处说法不一致。要点:

- `damage_mechanism_query` 返回的每个机理带**八段式**内容字段:`description`、`morphology`、`affected_materials`、`influencing_factors`、`susceptible_locations`、`prevention`、`detection_methods`、`related_damages`,对应 GB/T 30579-2022 第 4.4 条列出的八个方面。另有 `discriminator`(还缺什么证据)和 `excluded`(排除了什么、为什么)。
- `rbi_lookup` 必须同时给出原始风险等级和统一等级 L1~L5,统一等级查 `04_接口文档/risk_level_mapping.xlsx`,不得自行换算。
- `standard_clause_search` 是兜底检索,返回 `hits` 列表。
- 入参里的材质、介质、设备类型允许写 enums.json 登记过的别名(如 HCl、空冷器),由护栏归一化成规范值;条款库和摘录表里只许写规范值。

## 2.5 三个工具共用的返回外壳(不可改)

```json
{
  "status": "ok | out_of_domain | not_found | error",
  "in_domain": true,
  "result": {},
  "source": [],
  "message": ""
}
```

- `in_domain` 是**适用性标识**。查询条件超出条款覆盖范围时必须为 `false`,`result` 置空,并在 `message` 里说明超出了什么。
- **任何 `status="ok"` 的返回,`source` 数组不得为空。** 这是硬性红线。

# 第三部分 · 数据格式

## 3.1 条款结构化记录 `clauses.jsonl`(目标 ≥300 条)

```json
{
  "clause_id": "GBT30579-2022-6.7",
  "standard_code": "GB/T 30579-2022",
  "standard_name": "承压设备损伤模式识别",
  "clause_no": "6.7",
  "page": 51,
  "knowledge_type": "damage_mechanism",
  "title": "湿硫化氢破坏",
  "content_raw": "标准原文摘录,不得改写,≤300字",
  "applicable_conditions": {
    "equipment_type": [
      "塔",
      "换热器",
      "容器",
      "管道"
    ],
    "material": [
      "碳钢",
      "低合金钢"
    ],
    "medium": [
      "湿硫化氢"
    ],
    "temperature_c": [
      null,
      null
    ],
    "pressure_mpa": [
      null,
      null
    ],
    "other": "低pH、高pH且含氰化物、H2S浓度或分压等条件须综合判断"
  },
  "mechanism_detail": {
    "description": "",
    "morphology": [],
    "affected_materials": [],
    "influencing_factors": [],
    "susceptible_locations": [],
    "prevention": [],
    "detection_methods": [],
    "related_damages": []
  },
  "rbi_detail": {
    "likelihood": null,
    "consequence": null,
    "risk_level": null,
    "risk_level_unified": null,
    "inspection_interval_year": null,
    "inspection_methods": []
  },
  "extractor": "2025xxxx_张三",
  "verified_by": "",
  "version": "v1"
}
```

- `knowledge_type` 为 `damage_mechanism` 时填 `mechanism_detail`(八段式),为 `rbi` 时填 `rbi_detail`,另一个保持上例的空值结构。
- 不要手写这个 JSON。先填两份条款摘录表,再用 `04_接口文档/convert.py` 批量生成,流程见《资料获取与摘录表填写指南》第三部分。
- `mechanism_detail.affected_materials` 保留标准原文写法,不受枚举表约束;`applicable_conditions.material` 只写枚举表能表达的规范值,枚举表没有的材料写进 `other`。
- `clause_id` = 标准号去符号 + 年份 + 条款号,全局唯一,是整个系统的主键。
- `content_raw` 必须是原文,**不许润色**。
- `applicable_conditions` 里的枚举值只能从 `enums.json` 里选。"碳钢"和"低碳钢"混用会直接导致工具匹配失败。
- 区间一律 `[下限, 上限]`,开区间用 `null`。
- **抽不动的条款就跳过,宁可少,不许编。**

## 3.2 工具调用轨迹 `trajectories.jsonl`(≥200 条,多步 ≥40 条)

```json
{
  "traj_id": "UG-0001",
  "task_type": "multi_step",
  "input": {
    "equipment": "常压塔顶空冷器",
    "material": "碳钢",
    "medium": ["湿硫化氢", "氯化氢", "氯化铵"],
    "operating_condition": "操作温度110℃,压力0.1MPa,投用8年",
    "field_evidence": "塔顶水pH 5.8,氯离子42mg/L,铁离子4.1mg/L,上次检验未发现明显减薄",
    "question": "该部位铁离子超标的可能原因是什么?建议采取什么措施?"
  },
  "steps": [
    {
      "step": 1,
      "thought": "先根据材质与介质组合确定候选损伤机理",
      "tool": "damage_mechanism_query",
      "args": {"material": "碳钢", "medium": ["湿硫化氢","氯化氢","氯化铵"], "temperature_c": 110,
               "evidence": {"ph": 5.8, "cl_ppm": 42, "fe_ppm": 4.1, "wall_thinning": false}},
      "result": {},
      "observation": "候选机理:盐酸腐蚀、氯化铵腐蚀、湿硫化氢破坏。前两者需用结盐条件区分;湿硫化氢破坏证据不足,暂不能排除。"
    },
    {
      "step": 2,
      "thought": "需要区分两个候选机理,补充查询鉴别依据",
      "tool": "standard_clause_search",
      "args": {"keyword": "氯化铵结晶温度 注水点", "knowledge_type": "damage_mechanism"},
      "result": {},
      "observation": "铵盐结晶发生在注水点上游、结晶温度以上"
    },
    {
      "step": 3,
      "thought": "确定主导机理后查风险等级与检验建议",
      "tool": "rbi_lookup",
      "args": {"equipment_type": "换热器", "material": "碳钢", "mechanism": "盐酸腐蚀", "service_years": 8},
      "result": {},
      "observation": "返回原始风险等级与统一等级,附 RBI 条款出处"
    }
  ],
  "final_answer": {
    "conclusion": "结论正文,每条断言后标注依据",
    "basis": ["GBT30579-2022-5.19", "GBT30579-2022-5.1", "GBT30579-2022-6.7"]
  },
  "annotator": "2025xxxx_张三",
  "checked": false
}
```

`special_type` 是可选的顶层字符串字段，用于标识第 3.3 节的特殊轨迹类型：`exclusion`（排除型）、`insufficient_info`（信息不足型）、`out_of_domain`（超范围型）。例如排除型轨迹在顶层填写 `"special_type": "exclusion"`。普通轨迹如上例，省略此字段，不填写空字符串或 `null`。该字段与 `task_type` 独立，多步轨迹也可具有特殊类型；每条轨迹最多填写一种特殊类型。

**铁律**

- `final_answer.basis` 里的每个 `clause_id` 必须在 `clauses.jsonl` 中真实存在。校验脚本逐条比对,对不上的整条作废。
- 仅 `special_type="out_of_domain"` 的超范围型轨迹允许 `final_answer.basis` 为空数组 `[]`，但不得省略 `basis` 字段；其余任何类型（包括未填写 `special_type` 的普通轨迹）均不得为空。超范围型若填写了依据，仍须逐条核对 `clause_id` 是否存在。
- `task_type` 只有两个取值:一条轨迹里工具**调用次数** ≥3 为 `multi_step`,少于 3 次为 `single_step`。数的是调用次数,不是工具种类,同一工具调用多次也算,但每次调用都要有自己的理由,不能只换一个参数凑步数。`validate.py` 会核对 `task_type` 与调用次数是否一致。
- 被护栏拦截或执行异常的调用只记在 Harness 运行日志里(用于统计轨迹完整率),**不写进 `trajectories.jsonl`**。骨架里用 `Trajectory.to_record()` 导出数据集记录,遇到含拦截步骤的轨迹会拒绝导出。
- 一律用骨架里的 `save_jsonl()` 写文件。不要用 `python harness.py > xxx.jsonl` 重定向保存,Windows 下默认存成 GBK,`validate.py` 按 UTF-8 读会整批报错。
- `steps[].result` 必须是工具真实返回,不是手写的期望值。

## 3.3 特殊轨迹类型(务必留出配额)

以下三类样本数量少但价值极高,**要求至少各 15 条**:

| 类型 | `special_type` 值 | 说明 | 为什么重要 |
|---|---|---|---|
| **排除型** | `exclusion` | 最终结论是"排除某机理"或"不是腐蚀问题" | 现实中大量报警最后查明是仪表/取样/制造缺陷问题。模型只见过"是腐蚀"的样本,就会什么都往腐蚀上靠 |
| **信息不足型** | `insufficient_info` | 结论是"现有数据无法判定,需补充 XX 数据" | 教模型学会不乱答 |
| **超范围型** | `out_of_domain` | 查询条件超出条款适用范围,`in_domain=false`；允许 `final_answer.basis=[]` | 训练拒答能力,同时验证护栏 |

特殊轨迹必须在顶层填写对应的 `special_type`，普通轨迹不填。`validate.py` 按该字段分别统计三类的有效条数，与各至少 15 条的要求比对，自查模式只报告还缺多少条,`--final` 终验模式下不足即判失败(见第八部分)。只有通过结构、主键唯一性和依据引用检查的记录才计入配额，未标记的普通轨迹不计入；特殊类型是否与实际结论相符仍需人工复核。

# 第四部分 · Harness 实现要求

骨架代码在 `04_接口文档/harness_skeleton/`,四个模块填空。

1. **工具注册** — 工具名 → 函数 + 参数 schema 映射表
2. **执行循环** — 支持 ≥5 轮连续调用,逐轮记录 thought/tool/args/result,达到终止条件或轮次上限退出
3. **安全护栏** — 四类异常各 ≥3 个测试用例,拦截率 100%,不得误拦正常调用:
   - 工具名错误
   - 参数缺失
   - 超出适用范围(→ `in_domain: false`)
   - 输出格式不合规
4. **轨迹留痕** — 完整率 100%,失败和被拦截的调用也要记录

护栏测试要交两份用例,都不计入 200 条轨迹配额:

- `guardrail_cases.jsonl`:四类异常各 ≥3 条,应全部被拦截;
- `normal_cases.jsonl`:≥30 条正常调用,应全部放行,用来证明护栏没有写得过严。

格式和模板见 `04_接口文档/templates/`,用 `04_接口文档/harness_skeleton/run_guardrail_tests.py` 跑出报告。

# 第五部分 · 单智能体基础与可选创新方向

## 5.1 基础要求

本科生基础要求是完成**单智能体 + 工具调用 + Harness**闭环,从设备工况输入到带条款依据的结论输出,并预留研判、审查、建议三类智能体协作的扩展接口。三类智能体协作的实现属于后续扩展,审查体仅为可选加分项。

**技术指标(1)**:完成原型系统在魔搭(ModelScope)创空间的部署,提供可公开访问的网页界面;界面须完整展示工具调用过程(每一步的推理、调用的工具、传入参数、返回结果)与最终结论的条款依据,支持外部人员输入设备工况自行验证。

验收须提交**魔搭部署链接与界面截图**。具体操作和材料要求见 [技术指标验证方法](04_接口文档/技术指标验证方法.md)。

## 5.2 可选加分项:审查体

完成单智能体基础闭环后,有余力的同学可通过预留扩展接口接入审查体,检查结论中每条断言是否有 `clause_id` 支撑,发现无出处或引用错误则打回重做。该项仅作为可选加分项;技术指标(1)按第 5.1 节的魔搭部署与过程展示要求验收。

## 5.3 创新方向(选做,择一即可)

| 方向 | 内容 | 难度 |
|---|---|---|
| **A. 轨迹质量自动评分器** | 通过预留审查扩展接口选做评分器,评审单智能体产出的轨迹:出处是否存在、断言是否有依据、调用顺序是否合理、有无超范围硬答 | 中,**最推荐** |
| **B. 排除式推理智能体** | 让 agent 学会主动排除机理、或在证据不足时要求补充数据,而不是硬给结论 | 中 |
| **C. 条款冲突检测** | 同一工况下不同标准给出的判据不一致时,识别并标注冲突 | 中高 |
| **D. 护栏对抗测试生成** | 生成刁钻输入测试单智能体 Harness 的护栏,记录拦截结果与误拦情况 | 低 |

A 做出来会被团队实际使用;B 直接产出稀缺样本。C、D 作为学有余力的补充。

以本清单为准,`技术指标验证方法.md` 末尾的清单与此一致。第 10 周提交时,`05_提交区/` 下须包含:

- [ ] `normal_cases.jsonl` ≥30 条,全部放行

- [ ] 魔搭部署链接与界面截图:覆盖单步查询、多步查询、护栏拦截、超范围拒答四类情形,网页可公开访问,支持外部人员输入设备工况自行验证

`validate.py` 有两种模式:

- 自查模式(每周五):`python 04_接口文档/validate.py`。逐条检查 Schema、枚举、主键唯一、`basis` 引用的 clause_id 是否在条款库、`task_type` 与调用次数是否一致、`status=ok` 时 `source` 非空。条数只打印进度,不计为失败。
- 终验模式(第 10 周):`python 04_接口文档/validate.py --final`。在自查基础上,条款总数、两类知识覆盖、轨迹总数、多步条数、三类特殊轨迹任一不达标即判失败。

**任何一项不过,整批打回。** 格式全过不等于数据合格,原文是否抄对、返回是否真实调用所得、样本是否同一模板换参数,仍靠人工抽查。

# 第九部分 · 常见不合格情形

1. 结论正确但 `basis` 为空 —— 最常见,直接作废（`special_type="out_of_domain"` 的超范围型轨迹除外）
2. `basis` 里的 clause_id 在条款库里查不到 —— 编造出处
3. `content_raw` 被改写 —— 失去原文比对能力
4. 材质/介质写成自由文本而非枚举值 —— 工具无法匹配
5. 超出适用范围仍返回 `in_domain: true` 并给结论 —— 护栏失效
6. 200 条里 190 条是同一模板换参数 —— 场景多样性不足,对训练无价值
7. 自行增改工具名或字段名 —— 无法与另一条线数据合并,整批作废
